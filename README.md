# Венгерский алгоритм

Выполнил: Садилов Егор, ПМИ-2

Задание 4, вариант **а**: найти оптимальный вес полного паросочетания во взвешенном двудольном графе.

Программа реализует венгерский алгоритм, выводит выбранные ребра и их суммарный вес.
Поддерживаются поиск минимума и максимума, отрицательные веса и отсутствующие ребра.
Результат сохраняется в текстовый файл в папке `results`.

## Постановка задачи

Даны две доли `L` и `R`, каждая из `n` вершин. Ребра соединяют только вершины разных долей.
Нужно выбрать `n` ребер так, чтобы каждая вершина входила ровно в одну пару, а сумма весов была
минимальной или максимальной. Такое паросочетание называется полным (совершенным).

Полное **паросочетание** не означает, что сам граф обязан быть полным: некоторые ребра могут отсутствовать.
Если выбрать `n` пар невозможно, программа сообщает об этом. Для долей разного размера совершенного
паросочетания не существует, поэтому входная матрица должна быть квадратной.

## Формат входного файла

Первая строка содержит положительное число `n` - размер каждой доли.
Следующие `n` непустых строк содержат по `n` значений через пробел или табуляцию:

- число в строке `i`, столбце `j` - вес ребра `Li-Rj`;
- `x` - ребро отсутствует;
- `0` - существующее ребро нулевого веса.

Неверный размер матрицы, недопустимые символы приводят к сообщению об ошибке.

Например, файл [examples/small.txt](examples/small.txt):

```text
3
4 1 3
2 0 5
3 2 2
```

## Запуск

Для запуска нужен JDK 25. Команды выполняются из корня проекта.
```powershell
.\gradlew.bat run
```

Без аргументов используется `examples/small.txt` и поиск минимального веса.
Первый аргумент - путь к файлу, второй - режим `min` или `max`:
```powershell
.\gradlew.bat run --args="examples/small.txt min"
.\gradlew.bat run --args="examples/small.txt max"
.\gradlew.bat run --args="examples/sparse.txt min"
.\gradlew.bat run --args="examples/no-matching.txt min"
```
Файлы сохраняются как `results/<имя-входного-файла>-<режим>.txt`.

## Принцип работы

Используется вариант венгерского алгоритма с потенциалами и увеличивающими цепями.
В коде `rowPotential` и `columnPotential` хранят потенциалы, `matchedRowByColumn` - текущее
паросочетание, `minCostToColumn` - минимальную дополнительную стоимость перехода к столбцу,
а `previousColumn` - путь для восстановления увеличивающей цепи.

1. Для минимизации используются исходные веса. Для максимизации их знаки меняются на противоположные.
2. Потенциалы строк инициализируются минимумами существующих ребер, потенциалы столбцов - нулями.
3. Для очередной строки ищется свободный столбец. Если он занят, поиск продолжается через уже назначенную ему строку.
4. Приведенная стоимость ребра равна `cost(weight) − rowPotential[row] − columnPotential[column]`.
   Если продолжить цепь пока нельзя, потенциалы изменяются на минимальную величину `minDelta`, открывающую следующий столбец.
5. После нахождения свободного столбца назначения вдоль найденной цепи перестраиваются, и в паросочетание добавляется одна строка.
6. После обработки всех строк суммируются **исходные** веса выбранных ребер.

Для существующих ребер сумма потенциалов строки и столбца не превышает стоимость ребра, а выбранные ребра имеют нулевую
приведенную стоимость. Поэтому вес полного паросочетания совпадает с суммой потенциалов - нижней
границей веса любого полного паросочетания. Это обосновывает оптимальность ответа для задачи минимума;
смена знаков сводит к ней задачу максимума.

Отсутствующие ребра пропускаются. Если продолжить поиск цепи невозможно, полного паросочетания нет.
При нескольких оптимальных решениях выводится одно из них.

Временная сложность: **`O(n³)`**.

## Пример результата

Для `examples/small.txt` в режиме `min`:

```text
Input: examples/small.txt
Mode: minimum
Vertices: 3 + 3
Weight matrix:
4 1 3
2 0 5
3 2 2

Matching:
L1 -> R2 (weight: 1)
L2 -> R1 (weight: 2)
L3 -> R3 (weight: 2)
Optimal weight: 5
```

В режиме `max` выбираются пары `L1-R1`, `L2-R3`, `L30R2`, их суммарный вес - `11`.
Визуализация графа для варианта «а» не требуется; здесь приведен текстовый вывод программы.
