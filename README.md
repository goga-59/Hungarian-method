# Венгерский алгоритм

Выполнил: Садилов Егор, ПМИ-2

Задание 4, вариант **а**: найти оптимальный вес полного паросочетания во взвешенном двудольном графе.

Программа реализует венгерский алгоритм и выводит найденное полное паросочетание вместе с его суммарным весом.
Поддерживаются:
- поиск минимального и максимального суммарного веса;
- отрицательные веса рeбер;
- отсутствующие рeбра;
- определение случая, когда полного паросочетания не существует.

Результат работы программы выводится в консоль и сохраняется в текстовый файл в папке `results`.

## Постановка задачи

Дан взвешенный двудольный граф с двумя долями вершин `L` и `R`. В программе предполагается,
что каждая доля содержит по `n` вершин, поэтому граф задаeтся квадратной матрицей весов размером `n × n`.

Элемент матрицы `weights[i][j]` задаeт вес ребра между вершинами `Li` и `Rj`.
Если соответствующее ребро отсутствует, вместо веса используется значение `null`.
Необходимо найти полное паросочетание - набор из `n` ребер, в котором каждая вершина обеих долей входит ровно в одно выбранное ребро.

Например, для трeх вершин в каждой доле полное паросочетание может иметь вид:
```text
L1 -> R2
L2 -> R1
L3 -> R3
```

При этом ни одна вершина не используется дважды.

В зависимости от выбранного режима необходимо найти такое полное паросочетание, у которого сумма весов выбранных ребер будет:
- минимальной - режим `min`;
- максимальной - режим `max`.

Сам граф не обязан быть полным - некоторые рeбра могут отсутствовать.
Если из-за отсутствующих рeбер невозможно сопоставить каждой вершине одной доли отдельную вершину другой доли,
полного паросочетания не существует.

## Формат входного файла

Первая строка содержит положительное целое число `n` - количество вершин в каждой доле.
Следующие `n` непустых строк содержат по `n` значений через пробел или табуляцию:

- число в строке `i`, столбце `j` - вес ребра `Li-Rj`;
- `x` - ребро отсутствует;
- `0` - существующее ребро нулевого веса.

Например, файл [examples/small.txt](examples/small.txt):

```text
3
4 1 3
2 0 5
3 2 2
```

## Запуск

Для запуска нужен JDK 25.
Команды выполняются из корня проекта.
```powershell
.\gradlew.bat run
```

Если аргументы не указаны, используется `examples/small.txt` и поиск минимального веса.
Можно передать два аргумента: первый аргумент - путь к файлу, второй - режим `min` или `max`:
```powershell
.\gradlew.bat run --args="examples/small.txt min"
.\gradlew.bat run --args="examples/small.txt max"
.\gradlew.bat run --args="examples/sparse.txt min"
.\gradlew.bat run --args="examples/no-matching.txt min"
```

Результат сохраняется в файл: `results/<имя-входного-файла>-<режим>.txt`.

## Принцип работы

Используется вариант венгерского алгоритма с потенциалами и увеличивающими цепями.

Алгоритм последовательно рассматривает строки матрицы и для каждой строки пытается найти подходящий свободный столбец.
Если подходящий столбец уже занят другой строкой, алгоритм пытается перестроить ранее найденные назначения так,
чтобы включить новую строку в паросочетание.

В реализации используются следующие основные структуры:
- `rowPotential` - потенциалы строк;
- `columnPotential` - потенциалы столбцов;
- `matchedRowByColumn` - текущее паросочетание: какая строка назначена каждому столбцу;
- `minCostToColumn` - минимальная приведeнная стоимость достижения каждого столбца;
- `previousColumn` - предыдущий столбец в увеличивающей цепи;
- `visitedColumns` - столбцы, уже рассмотренные во время текущего поиска.

Алгоритм выполняется следующим образом:
1. Для минимизации используются исходные веса. Для максимизации их знаки меняются на противоположные.
2. Потенциалы строк инициализируются минимумами существующих ребер, потенциалы столбцов - нулями.
3. Для очередной строки ищется свободный столбец. Если он занят, поиск продолжается через уже назначенную ему строку.
4. Приведенная стоимость ребра равна `cost(weight) − rowPotential[row] − columnPotential[column]`.
   Если свободный столбец пока не найден, потенциалы корректируются
   на величину minDelta, что позволяет продолжить поиск.
5. После нахождения свободного столбца назначения вдоль найденной цепи перестраиваются, и в паросочетание добавляется одна строка.
6. После обработки всех строк суммируются **исходные** веса выбранных ребер.

Отсутствующие ребра пропускаются. Если продолжить поиск цепи невозможно, полного паросочетания нет.
При нескольких оптимальных решениях выводится одно из них.

Временная сложность: **`O(n³)`**.

## Пример работы

Для `examples/small.txt` в режиме `min`:

```text
3
4 1 3
2 0 5
3 2 2
```

Результат работы программы:

```text
Input: examples/small.txt
Mode: minimum
Weight matrix:
   R1 R2 R3
L1  4  1  3
L2  2  0  5
L3  3  2  2

Matching:
L1 -> R2 (weight: 1)
L2 -> R1 (weight: 2)
L3 -> R3 (weight: 2)
Optimal weight: 5
```

В режиме `max` выбираются пары `L1-R1`, `L2-R3`, `L3-R2`, их суммарный вес - `11`.
